## 2. Модель повёрнутого аппарата (для будущих правок)
- Позиция: `{x, y, rot}` + необязательные `ang` (−45°…45°, поворот относительно `rot`) и `sw` (id косой стены). Без `ang` всё бит-в-бит как раньше — главное требование во всех шагах.
- Для повёрнутого `x, y` — левый верхний угол **охватывающего** прямоугольника, `bbox` возвращает его же.
- Помощники рядом с `bbox`: `posAng`, `baseSize`, `unitPoly`, `unskewPos`, `skewRotAng`, `skewWallPos`, `skewPlace`, `skewNearest`, `unitInRoom`, `skewTransform`, `rectPoly`, `frontPoly`, `frontDir`, `polyHit`, `polyGap`, `polyInRoom`, `pointInPoly`, `unitWallDist`, `unitWallSpan`.
- Отрисовка: внешний `<g transform="skewTransform(...)">`, внутри — прежний рисунок базового прямоугольника.
- `unitPlace` даёт `kind:'skew'` (поле «От угла со стеной N, мм» — `data-pos="skt"`).
- Зонты: `hoods()` для повёрнутых — элементы с `poly`, `len`, `area`; `hotGroups` пока по охватывающему прямоугольнику.

## 5. Мост через GitHub — уроки (обязательно)
- **id команды уникален навсегда.** Наблюдатель запоминает «ветка + id» в `bridge-state.txt` и помечает команду **до** выполнения. Повтор того же id молча пропускается. Брать id по текущему московскому времени `ГГГГММДД-ЧЧММ` и сверять с уже использованными. При сбое (компьютер уснул посреди команды) — повторять с **новым** id.
- **В `main` из облака напрямую не пушить:** наблюдатель перед `git push origin main` не делает pull, и его push отклоняется (так было с коммитом правила 04.11; лечилось `git pull --rebase --autostash origin main` + `git push` на компьютере). Правки `CLAUDE.md` — через пользователя.
- Перед `run` ветку перестраивать на свежий `origin/main`, сохраняя `bridge/` и `notes/` (`git checkout -f -B <ветка> origin/main`, вернуть копии, `push --force-with-lease`).
- Ждать ответа — собственным фоновым Bash-циклом (`run_in_background`), агенту Haiku `sleep` запрещён. GPT на `high` идёт до 1,5 ч.
- `bridge/result/index.html` приходит с CRLF — сравнивать после `tr -d '\r'`.
- Лимит Codex: в `codex-log.txt` «You've hit your usage limit… try again at …» — команда возвращается `done` без правок; отклонить (`reject`) и ждать сброса.
- Наблюдатель общий с параллельной сессией — договариваться через `send_message`.
