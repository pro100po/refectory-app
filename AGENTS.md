# Правила проекта refectory-app

Общие договорённости пользователя действуют и здесь. Роль определяется конкретным поручением: агент может быть ведущим, исполнителем или проверяющим. Не считать каждого Codex исполнителем автоматически.

Предметные решения находятся в [docs/DOMAIN_RULES.md](docs/DOMAIN_RULES.md). Порядок работы — в [docs/WORKFLOW.md](docs/WORKFLOW.md), правила исполнителя — в [docs/EXECUTOR.md](docs/EXECUTOR.md), текущее состояние перехода — в [notes/infrastructure-status.md](notes/infrastructure-status.md). При продолжении сверяй документы с фактическим состоянием проекта.

Ведущий по общим договорённостям от 10.11.2026 — GPT-6.1 Sol/high (gpt-6.1-sol); это правило не переключает текущий чат. Сразу после цели пользователя, до первого поиска или анализа, и между всеми содержательными этапами ведущий выполняет маршрутизацию: выбирает программу для механических действий или помощника подходящей модели/effort для исследования, анализа, плана/задания, реализации, проверки, диагностики/повтора, документов/отчёта. Ведущий отвечает за общение, границы, согласование, назначения, разрешение противоречий, ключевые доказательства и принятие результата, делегируя содержательную работу без полного дублирования. Если возможностей Sol недостаточно, этап поручают Astra с effort по сложности. До изменений пользователь согласует цель и план пункта; подготовительный делегированный анализ разрешён только на чтение. Затем шаги выполняют подряд, показывая ожидаемый результат, без повторного согласования назначений. Самостоятельная техническая работа означает выполнение через назначенных помощников и программы без перекладывания на пользователя, а не выполнение всех этапов ведущим. Содержательная приёмка — минимум Sol/medium, для сложного изменения отдельным от исполнителя проверяющим; короткий ответ из готового контекста и простую проверку ведущий может выполнить сам.

Каждое поручение исполнителю содержит роль, цель, ожидаемое поведение, область изменений, ограничения и проверки. Для отдельного запуска используется явно указанный файл задания данного запуска; исполнитель не предполагает, что ему назначен общий TASK.md. Не меняй посторонние файлы, не удаляй чужую работу и не выполняй широкий откат. Применяй предметные правила к изменениям приложения, не распространяя ограничения одного задания на все инфраструктурные задачи.

В проекте приложение находится в `index.html`; сохраняй существующий русский интерфейс и стиль. Архив `versions/` изучай или меняй только когда это нужно явно порученной задаче. Сохранение и публикация выполняются только в разрешённом объёме и после проверки. Промежуточные принятые шаги сохраняются локально, полный пункт публикуется после завершения.
